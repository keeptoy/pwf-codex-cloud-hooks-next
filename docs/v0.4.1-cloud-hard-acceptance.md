### 1. push治理提交并做发布前只读核对

维护者先把当前`0.4.1`分支push到远端并核对exact operator HEAD，再确认GitHub尚不存在`v0.4.1` tag或Release。
本地探路已在2026-08-22通过GitHub API观察到两个端点均为HTTP 404；正式执行仍必须重查。认证、网络或其他HTTP错误
只能记`UNKNOWN`，不能冒充“不存在”。

~~~powershell
$tag = "v0.4.1"
$tagSource = "99885b854bd9621c3340e99f031bf83ceb58414d"
$repository = "keeptoy/pwf-codex-cloud-hooks-next"

git status --short --branch
if (git status --porcelain) { throw "P9-C blocked: working tree is not clean" }
$operatorHead = (git rev-parse HEAD).Trim()
git push origin 0.4.1
$remoteBranchLine = git ls-remote origin refs/heads/0.4.1
if (-not $remoteBranchLine) { throw "P9-C blocked: remote branch was not found" }
$remoteBranchHead = ($remoteBranchLine -split '\s+')[0]
if ($remoteBranchHead -ne $operatorHead) { throw "P9-C operator HEAD mismatch: $remoteBranchHead" }
if ((git rev-parse "$tagSource^{commit}").Trim() -ne $tagSource) {
  throw "P9-C blocked: exact tag source is unavailable"
}
if (git tag --list $tag) { throw "P9-C blocked: local tag already exists; audit it, do not replace it" }

$tagProbe = (gh api --include "repos/$repository/git/ref/tags/$tag" 2>&1 | Out-String)
$tagProbeExit = $LASTEXITCODE
if ($tagProbeExit -eq 0) { throw "P9-C blocked: remote tag already exists; audit it, do not move it" }
if ($tagProbe -notmatch '(?m)^HTTP/\S+ 404\b') {
  throw "P9-C tag absence is UNKNOWN; stop and repair remote access: $tagProbe"
}
$releaseProbe = (gh api --include "repos/$repository/releases/tags/$tag" 2>&1 | Out-String)
$releaseProbeExit = $LASTEXITCODE
if ($releaseProbeExit -eq 0) { throw "P9-C blocked: Release already exists; audit it, do not recreate it" }
if ($releaseProbe -notmatch '(?m)^HTTP/\S+ 404\b') {
  throw "P9-C Release absence is UNKNOWN; stop and repair remote access: $releaseProbe"
}
"PWF_P9C_OPERATOR_HEAD=$operatorHead"
"PWF_P9C_REMOTE_ABSENCE_PREFLIGHT=PASS"
~~~

只有branch HEAD一致且两个GitHub API查询都明确返回HTTP 404才继续。发现同名tag或Release立即停止；不得删除、
force-update或换一个source继续。

### 2. 从exact tag source重建待上传资产

使用全新临时clone，不复用当前工作树或旧临时产物。脚本会双构建ZIP、核对determinism/size/SHA/archive contract，
再把一份ZIP与同一tag source中的bootstrap复制到独立staging目录；目录已存在就fail closed。

~~~powershell
$tagSource = "99885b854bd9621c3340e99f031bf83ceb58414d"
$repoUrl = "https://github.com/keeptoy/pwf-codex-cloud-hooks-next.git"
$stageRoot = Join-Path ([IO.Path]::GetTempPath()) "pwf-v0.4.1-p9c-publication"
$sourceRoot = Join-Path $stageRoot "source"
$assetRoot = Join-Path $stageRoot "assets"
if (Test-Path -LiteralPath $stageRoot) { throw "P9-C staging directory already exists: $stageRoot" }
New-Item -ItemType Directory -Path $assetRoot | Out-Null
git clone --no-checkout $repoUrl $sourceRoot
git -C $sourceRoot checkout --detach $tagSource
if ((git -C $sourceRoot rev-parse HEAD).Trim() -ne $tagSource) { throw "tag source checkout mismatch" }
if (git -C $sourceRoot status --porcelain) { throw "tag source checkout is dirty" }

$zipA = Join-Path $stageRoot "candidate-a.zip"
$zipB = Join-Path $stageRoot "candidate-b.zip"
$zip = Join-Path $assetRoot "pwf-codex-cloud-hooks-v0.4.1.zip"
$bootstrap = Join-Path $assetRoot "init-cloud-sandbox-v0.4.1.bash"
python "$sourceRoot/tools/import_upstream_runtime.py" check
python "$sourceRoot/tools/build_release.py" build --output $zipA
python "$sourceRoot/tools/build_release.py" check --archive $zipA
python "$sourceRoot/tools/build_release.py" build --output $zipB
python "$sourceRoot/tools/build_release.py" check --archive $zipB
$zipHashA = (Get-FileHash -Algorithm SHA256 $zipA).Hash.ToLowerInvariant()
$zipHashB = (Get-FileHash -Algorithm SHA256 $zipB).Hash.ToLowerInvariant()
if ($zipHashA -ne $zipHashB) { throw "candidate builds are not byte-identical" }
if ($zipHashA -ne "94f12fca8157b97a613a04f1857b6688c8d94650ac566c573345760ff6bb6291") {
  throw "candidate SHA-256 drift: $zipHashA"
}
if ((Get-Item -LiteralPath $zipA).Length -ne 85910) { throw "candidate size drift" }
Copy-Item -LiteralPath $zipA -Destination $zip
Copy-Item -LiteralPath (Join-Path $sourceRoot "init-cloud-sandbox-v0.4.1.bash") -Destination $bootstrap
$bootstrapHash = (Get-FileHash -Algorithm SHA256 $bootstrap).Hash.ToLowerInvariant()
if ($bootstrapHash -ne "1832db08c16b4f7fde88df2699384f1fff8e324909b0e024cb6ef216aea30a43") {
  throw "bootstrap SHA-256 drift: $bootstrapHash"
}
if ((Get-Item -LiteralPath $bootstrap).Length -ne 21565) { throw "bootstrap size drift" }
bash -n $bootstrap

"PWF_P9C_TAG_SOURCE_HEAD=$tagSource"
"PWF_P9C_ZIP_SHA256=$zipHashA"
"PWF_P9C_BOOTSTRAP_SHA256=$bootstrapHash"
"PWF_P9C_ASSET_STAGING=$assetRoot"
"PWF_P9C_ASSET_REPRODUCTION=PASS"
~~~

只有最后五行全部出现且命令明确exit 0，才能使用该staging目录；不得从文件管理器混入另一份同名资产。

## 4. Path-safety acceptance delta

本版本新增 installer 路径拓扑边界：`hooks` parent、runtime root 或 runtime 内部 entry 若为 symlink、junction 或
special path，install、repair 与 uninstall 都必须在 backup 和任何 shared/runtime mutation 前 fail closed。uninstall
对 unknown 普通文件/目录的 recovery/cleanup 合同保持不变。

本增量由 4.1 自动发现的 portable installer tests 与 published round-trip transition oracle 验证。Linux runner 的原始
TAP 必须明确显示下列行为通过，并且整套 runner 为 0 fail、0 skip：

- linked hooks parent 在 install/uninstall 前拒绝；
- linked runtime root 与 nested runtime link 在 uninstall 前拒绝；
- nested FIFO 在 backup/mutation 前以 `BLOCKED_UNSAFE_RUNTIME_PATH` 拒绝；
- unknown regular file/directory 仍成功备份并卸载。

B、D、E 黑盒提示词、Host ABI、adapter-only policy 与 runtime dispatch 均未改变，原样复用稳定模板。C 只补充了
B→C 权限交接：明确结束 B 的单次无工具/不读文件观察限制，并仅开放 canonical planning fixture 所需的 bounded read
与 apply_patch；canonical 内容、预期 acknowledgment 和 production behavior 均不变。Windows 本地 SKIP 只证明测试被
正确分流，不能替代上述 Linux FIFO PASS。
