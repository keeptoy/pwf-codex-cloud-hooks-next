# v0.3.3-dev Cloud hard acceptance

> 目的：为 pristine catch-up runtime successor 冻结 Source/Candidate 与未来 Published Release 两条独立
> Cloud 验收通道。当前状态：`PENDING_R5_SC`；本文件不证明 tag、Release、公开资产或 rollback 晋级成立。

## 1. 身份与授权边界

| 项目 | 当前值 |
|---|---|
| candidate source | `v0.3.3-dev`；精确 commit 由执行时记录 |
| accepted baseline | immutable `v0.3.2` |
| bootstrap | `init-cloud-sandbox-v0.3.3-dev.bash`；默认 SHA 为 64 位 zero hash |
| Release state | 未 seal、未发布 |
| Cloud state | `PENDING_R5_SC` / `PENDING_R5_PR` |

本 gate 只验证已授权的 catch-up overlay retirement，不授权 tag、Release、GitHub `Latest`、production
rollback 或 Product Phase 4。Source/Candidate PASS 只能绑定执行时记录的精确 commit 和由它构建的 ZIP；
Published Release PASS 只能绑定未来 immutable tag 与公开下载字节。

## 2. 两条通道

| 通道 | 输入身份 | 安装方式 | 当前状态 |
|---|---|---|---|
| R5-SC Source/Candidate | 选定 branch/commit 的 tagless checkout | 从 source 双构建/check ZIP，以显式本地 `HOOKS_URL` / `HOOKS_SHA256` override 调用 bootstrap | `PENDING_R5_SC` |
| R5-PR Published Release | immutable tag、公开 bootstrap 与 ZIP | bootstrap 使用自身默认 URL/SHA 下载并安装 | `PENDING_R5_PR` |

两条通道不得共用容器、安装状态或 B～F 结果。R5-SC 不运行 publication-only tag/source oracle；R5-PR
不能用 workspace 中的同名 bootstrap、ZIP、installer、builder 或 importer 代替公开资产。

## 3. 共同前置不变量

- global `planning-with-files v3.8.2` Skill 与 pinned manifest 逐字一致；
- Managed policy 只注册 absolute `hook_adapter.py`；
- installed runtime 的四个 `runtime/upstream/*` 文件全部来自 pristine pinned archive；
- current tree、ZIP 和 installed inventory 均不含 active compatibility overlay ledger 或 patcher；
- `owned-catchup.py` 不调用 upstream CLI `main()`，helper closure 不进入 CLI session/runtime/plan/render 分支；
- Fresh、UserPromptSubmit、real Resume、doctor 与 post-resume residue 均需独立通过。

## 4. R5-SC setup

在新的 Source/Candidate Cloud 中记录 checkout 身份，运行 tagless portable suite、importer check、静态编译和
bootstrap 语法检查。双构建必须字节一致，随后只用显式本地 override 安装：

```bash
set -Eeuo pipefail

RUNBOOK_HEAD="$(git rev-parse HEAD)"
python3 tools/import_upstream_runtime.py check
node --check install.js
bash -n init-cloud-sandbox-v0.3.3-dev.bash

ZIP_A="$(mktemp --suffix=.zip)"
ZIP_B="$(mktemp --suffix=.zip)"
python3 tools/build_release.py build --output "$ZIP_A"
python3 tools/build_release.py build --output "$ZIP_B"
python3 tools/build_release.py check --archive "$ZIP_A"
python3 tools/build_release.py check --archive "$ZIP_B"
cmp "$ZIP_A" "$ZIP_B"

ACTUAL_ZIP_SHA256="$(sha256sum "$ZIP_A" | awk '{print $1}')"
HOOKS_URL="file://$ZIP_A" HOOKS_SHA256="$ACTUAL_ZIP_SHA256" \
  bash init-cloud-sandbox-v0.3.3-dev.bash all
```

输出必须记录精确 `RUNBOOK_HEAD`、排除的 publication-only suite、ZIP SHA/size、installer doctor 和最终
`V033_DEV_SOURCE_CANDIDATE_SETUP=PASS`。分支名不是验收身份。

## 5. B：Fresh SessionStart

在没有旧 transcript/plan 残留的新会话验证 canary、canonical plan 与无 catch-up 时的安静行为；禁止手工
调用 adapter 结果冒充真实 Hook。

## 6. C：UserPromptSubmit

建立 scoped planning state 后，在真实 prompt 中验证 canary → canonical owned plan 顺序、bounded context 和
`managed_legacy` 默认行为；不得启用 Phase 4 marker。

## 7. D：真实 Resume catch-up

由第一会话写入 planning update 和尾部 sentinel，使用平台 Resume 进入第二会话。必须证明 Host transcript
identity、immutable byte capture、normalization、dedup、head/tail budget 与 report total budget，并确认
patched CLI branch、global Skill runtime 和 ambient store guessing 均未参与。

## 8. E：失败与降级

至少覆盖 transcript identity mismatch、malformed/oversized JSONL、plan child failure、catch-up child failure
和 unknown installed drift：内容注入 fail closed，单一 advisory child 对 Codex loop fail open，canary 与已经
验证的 plan 不因 catch-up failure 丢失。

## 9. F：Source/Candidate post-resume

从 source checkout 的 installer 执行 doctor，核对 exact installed inventory、adapter-only policy、owned runtime
hash/mode、global Skill pristine 与 snapshot residue。R5-SC 结果只属于当次精确 commit/ZIP。

## 10. Published Release 通道

R5-PR 只有在新 identity 完成 seal、immutable publication 和公开资产 checksum 登记后才能执行。默认下载链
不得接受 moving branch、`latest`、zero hash 或本地 override。

### 10.1 R5-PR Fresh through Resume

在与 R5-SC 完全独立的新 Cloud 环境，从公开 Release URL 下载 bootstrap，校验其登记 SHA，让 bootstrap 以
默认 URL/SHA 下载 ZIP；随后重新执行 B～E，不复用 Source/Candidate 的容器、安装或会话数据。

### 10.2 R5-PR post-resume doctor、inventory、policy 与 residue

Setup 临时目录可能已被 bootstrap 正常删除，因此 post-resume 复验必须重新下载同一 immutable ZIP：

```bash
set -Eeuo pipefail

readonly ZIP_URL="https://github.com/keeptoy/pwf-codex-cloud-hooks-next/releases/download/v0.3.3-dev/pwf-codex-cloud-hooks-v0.3.3-dev.zip"
VERIFY_DIR="$(mktemp -d)"
ZIP="$VERIFY_DIR/pwf-codex-cloud-hooks-v0.3.3-dev.zip"
PACKAGE_ROOT="$VERIFY_DIR/extracted/pwf-codex-cloud-hooks"

curl -fL "$ZIP_URL" -o "$ZIP"
# publication gate 写入并核对 immutable size/SHA 后才能继续。
python3 tools/build_release.py check --archive "$ZIP"
python3 tools/import_upstream_runtime.py check --destination "$PACKAGE_ROOT/runtime/upstream"
node "$PACKAGE_ROOT/install.js" doctor --json --codex-home /opt/codex

SNAPSHOT_LEFTOVERS="$(find /opt/codex -type d -name '.pwf-plan-snapshot-*' -print | wc -l)"
test "$SNAPSHOT_LEFTOVERS" -eq 0
echo "SNAPSHOT_LEFTOVERS=0"
```

实际脚本还必须先用同源 `tools/build_release.py check` 核验 ZIP boundary，再解压后使用 ZIP 内同源 importer、
installer 和 Python 深度断言核对 pristine upstream hashes、installed manifest inventory 与 adapter-only policy；
不得调用 workspace 工具。
