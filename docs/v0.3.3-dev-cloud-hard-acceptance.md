# v0.3.3-dev Cloud hard acceptance

> 目的：为 pristine catch-up runtime successor 冻结可直接重放的 Source/Candidate Cloud 验收，以及未来
> Published Release 的独立消费模板。当前状态：PENDING_R5_SC；本文不证明 tag、Release、公开资产、
> GitHub Latest 或 rollback 晋级成立。
>
> 本手册继承 v0.3.2 已经跑通的双通道 B～F 黑盒骨架，但按 v0.3.3-dev 的 current machine contracts
> 替换 runtime、inventory 与 supply-chain 断言。任何历史数字、脚本或资产身份都不能直接复制成当前 PASS。

## 0. 执行路线

v0.3.3-dev 目前只授权第一条通道。第二条通道必须等新的 immutable identity 完成 seal、publication 和
公开重新下载复核后才能解锁。

| 顺序/通道 | 身份与用途 | 当前状态 |
|---|---|---|
| 第一步 R5-SC Source/Candidate | Cloud 选择开发/验证分支；PASS 绑定运行时记录的完整 commit，以及从该 checkout 双构建出的精确 ZIP；使用显式本地 HOOKS_URL/HOOKS_SHA256 override 安装 | PENDING_R5_SC；当前唯一可执行通道 |
| 第二步 R5-PR Published Release | 固定未来 immutable tag/source；从公开 Release URL 校验 bootstrap，让 bootstrap 用自身默认 URL/SHA 下载 ZIP，再独立重跑 B～F | PENDING_R5_PR；publication gate 未关闭，禁止执行 |

分支只是运输入口，不是验收身份。R5-SC PASS 只属于当次输出的 RUNBOOK_HEAD、实际 ZIP 字节和独立
Cloud 环境；它不证明 tag 或公开 Release 成立。R5-PR PASS 只属于未来登记的 immutable tag、公开
bootstrap/ZIP 字节、filename、size、SHA 和默认下载链，不能由 workspace 中的同名文件代替。

两条通道不得共用容器、安装状态或 B～F 结果。planning scope、transcript 与任何 setup 残留同样不得
跨通道复用。正式顺序为：

1. 新建或 Reset cache 的 Node 22 Cloud 环境，运行第 4 节 R5-SC setup。
2. setup 必须输出 V033_DEV_SOURCE_CANDIDATE_SETUP=PASS；随后创建新 task，依次执行第 5～9 节。
3. 保存完整原始输出并弃用该 Cloud 环境。任一步失败立即停止，不 repair 掩盖失败。
4. 只有 seal/publication gate 把第 10 节全部 placeholder 替换为经过复核的 immutable 值后，才在另一个
   Fresh Cloud 环境执行 R5-PR，并从头重跑相同 B～F fixture。
5. 两条通道即使分别 PASS，也只回传证据；不自行 tag、发布、提升 Latest 或改变 rollback 角色。

setup 内的 direct adapter probe 或 doctor 只证明安装链静态健康，不是 Runtime 自动注入的黑盒证据。
Fresh、UserPromptSubmit 与 real Resume 必须在 setup 结束后的新 agent/task 中观察。

## 2. 硬停止条件

遇到任一情况立即停止并保存完整输出：

- 工作树在 setup 前不干净，或无法记录完整 RUNBOOK_HEAD；
- Node major 不是 22，或目标 CODEX_HOME 已有 managed runtime；
- bootstrap 默认 SHA 不是 64 位 zero hash，或无 override 时不再 fail closed；
- portable Linux suite 出现 fail/skip，或 publication-only oracle 混入 tagless R5-SC；
- 两次 ZIP 不逐字一致、entry count 不是 21、bootstrap 进入 ZIP，或 ZIP 含 patcher/overlay ledger；
- importer、pristine hash、helper allowlist/closure、Git mode 或 extracted replay 任一失败；
- global PWF Skill 不 pristine，Managed policy 不再 adapter-only，或 installed inventory 不是 exact current set；
- Fresh 缺少 SessionStart/UserPromptSubmit canary，或黑盒证据由手工 adapter/runtime 调用伪造；
- canonical plan 未自动注入、出现 Phase 4 marker，或 canary/catch-up/plan 顺序不符合 current contract；
- real Resume 缺少 catch-up、tail marker、canonical plan，或 SessionStart source 仍是 startup；
- post-resume doctor 不健康、repairable、存在 error/blocker、inventory/hash/mode drift 或 snapshot residue；
- R5-PR placeholder 尚未全部替换，或者尝试使用 moving branch、latest、zero hash、本地 override或 workspace 工具。

失败后不得放宽断言、手工执行 Hook/runtime 拼接 PASS，也不得 repair 后继续计为同一次 PASS。产品或字节
修复后必须从对应通道的 Fresh setup 重新开始；任何公开资产变化都需要新身份、新 hash 和重新验收。

## 10. Published Release 通道（publication-gated）

R5-PR 只有在新 identity 完成 seal、immutable publication 和公开双资产重新下载复核后才能执行。当前
placeholder 是硬停止合同，不是待执行命令：

| placeholder | publication gate 必须写入的值 |
|---|---|
| __PUBLICATION_TAG__ | 新的 immutable tag；不能是 moving branch 或 v0.3.3-dev development identity |
| __PACKAGE_VERSION__ | 与 tag/package/contract 一致的 sealed version |
| __BOOTSTRAP_NAME__ / __BOOTSTRAP_SHA256__ / __BOOTSTRAP_SIZE__ | 公开 external bootstrap 的 exact identity |
| __ZIP_NAME__ / __ZIP_SHA256__ / __ZIP_SIZE__ | 公开 ZIP 的 exact identity |
| __RELEASE_URL__ | 对应 exact tag 的 immutable GitHub Release 页面 |

任一 placeholder、zero hash 或 pending marker仍存在时，R5-PR=NO_GO。

### 10.1 R5-PR setup 与 Fresh through Resume

publication gate 关闭后，在与 R5-SC 完全独立的新 Node 22 Cloud 环境执行。脚本不得设置 HOOKS_URL/

## 12. 失败取证与结果写回

每个通道至少保存：

- Cloud 环境是否 Fresh、Node major、setup 完整 stdout/stderr；
- Source/Candidate 的 RUNBOOK_HEAD、排除 suite、runner tests/pass/fail/skipped、ZIP size/SHA；
- B～E 每条原始提示词、模型原始回复、实际 Resume source 与 Unsynced messages；
- doctor JSON、installed inventory、policy deep assertion、pristine/helper 断言与 residue 输出；
- 失败发生的精确步骤、首次错误输出和停止点；不得只保存 repair 后结果。

当前结果表：

| Gate | 状态 | 证据 |
|---|---|---|
| local/focused/full | LOCAL_PASS | G4/G6 本地证据已写入活动 planning；不代替 Linux/Cloud |
| R5-SC Source/Candidate | PENDING_R5_SC | 等待独立 Cloud 的第 4～9 节 |
| seal/publication | NOT_AUTHORIZED | development bootstrap 继续 zero hash |
| R5-PR Published Release | PENDING_R5_PR | placeholder 未关闭，不可执行 |
| final Cloud hard acceptance | PENDING | 不能由单一通道 PASS 形成 |
| Latest/rollback promotion | NOT_AUTHORIZED | 另行维护者决策 |

R5-SC 通过后，只把该行更新为精确 commit/ZIP 与 Cloud evidence；不要提前删除 R5-PR pending。
只有两条通道在独立 Fresh 环境分别 PASS、所有 placeholder 已由 immutable identity 替换且证据写回，
才可以形成 CLOUD-HARD-ACCEPTANCE-PASS 结论。
