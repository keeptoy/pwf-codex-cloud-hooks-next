# v0.4.0-dev F3 Cloud lifecycle runbook

本文件是 `v0.4.0-dev` F3 Git-backed lifecycle 的版本化执行协议。F3A 建立了生命周期 foundation；F3B1 只把
runtime source transaction、smart/autonomous validation DAG、tamper 边界和 evidence record 物化为可复制协议。
**F3B1 不授权真实 prepare、activate、disarm 或 Cloud lifecycle**；F3B2、F3B3、F3B4 与 F3C 必须分别另行授权。

稳定的 Source/Candidate、Published Release 与异步命令规则仍见
[`Cloud hard acceptance template`](cloud-hard-acceptance-template.md)。本文件不进入 Release ZIP，不是 managed writer，
也不改变 runtime bundle inventory。

<a name="f3-safety-boundary"></a>

## 1. 安全边界

- 只接受 Git 管理的 scoped active plan；`.planning/.active_plan` 必须精确指向 `PLAN_ID`。
- preparation commit 包含完整但 inert 的 profile state，绝不包含 `.pwf-codex-managed`。
- activation commit 必须直接以 preparation commit 为 parent，并且只能增加 `.pwf-codex-managed`。
- autonomous armed 期间 `task_plan.md` 字节冻结；修改计划必须先提交 disarm，再重新 prepare/activate。
- activation token 是公开的 repository workflow intent，不是 secret、身份、账户授权或签名凭据。
- cache、environment variable、setup secret、模型声明和未提交 worktree 都不是 correctness/consent boundary。
- managed runtime 始终只读。不要用本 runbook 导入 upstream/managed writer，也不要把 planning state 加入 Release。
- 任一长命令必须取得明确最终 `exit_code`；只有 stdout 分片或 `session_id` 时继续轮询，无法取得最终状态只能记为
  `INCOMPLETE/UNKNOWN`。

<a name="f3-runtime-source-transaction"></a>

## 2. Cloud runtime source exact transaction

Cloud 的 setup 在 cold/cached environment 建立阶段运行，maintenance 在命中缓存后运行；二者不是同一个 shell，不能依赖
setup 中临时 `export` 的变量或缓存目录。F3B live gate 必须在 environment 配置中显式提供下列六项输入，并把下面的
Bash block **原样分别复制到 setup 与 maintenance**：

```text
PWF_F3_RUNTIME_SOURCE_REPOSITORY=https://github.com/OWNER/REPOSITORY.git
PWF_F3_RUNTIME_SOURCE_HEAD=<40 lowercase hex>
PWF_F3_CANDIDATE_SHA256=<64 lowercase hex>
PWF_F3_CODEX_HOME=/opt/codex
PWF_F3_MANAGED_REQUIREMENTS=/etc/codex/requirements.toml
PWF_F3_SKILL_ROOT=/root/.agents/skills/planning-with-files
```

setup and maintenance must copy the same exact transaction block。任何一边都不得换成 moving branch、默认分支、缓存
receipt、`latest`、当前 checkout 或“本次构建出来的 SHA”。维护者在 F3B2 前冻结 expected HEAD/SHA，transaction 只核对，
不自证。

```bash
set -Eeuo pipefail

: "${PWF_F3_RUNTIME_SOURCE_REPOSITORY:?missing exact runtime source repository}"
: "${PWF_F3_RUNTIME_SOURCE_HEAD:?missing exact runtime source HEAD}"
: "${PWF_F3_CANDIDATE_SHA256:?missing exact candidate SHA-256}"
: "${PWF_F3_CODEX_HOME:?missing CODEX_HOME}"
: "${PWF_F3_MANAGED_REQUIREMENTS:?missing managed requirements path}"
: "${PWF_F3_SKILL_ROOT:?missing pristine Skill root}"
case "$PWF_F3_RUNTIME_SOURCE_HEAD" in (*[!0-9a-f]*|'') exit 64;; esac
test "${#PWF_F3_RUNTIME_SOURCE_HEAD}" -eq 40
case "$PWF_F3_CANDIDATE_SHA256" in (*[!0-9a-f]*|'') exit 64;; esac
test "${#PWF_F3_CANDIDATE_SHA256}" -eq 64

TRANSACTION_ROOT="$(mktemp -d)"
trap 'rm -rf -- "$TRANSACTION_ROOT"' EXIT
SOURCE_ROOT="$TRANSACTION_ROOT/source"
CANDIDATE_ZIP="$TRANSACTION_ROOT/pwf-candidate.zip"
git init -q "$SOURCE_ROOT"
git -C "$SOURCE_ROOT" remote add origin "$PWF_F3_RUNTIME_SOURCE_REPOSITORY"
git -C "$SOURCE_ROOT" fetch --depth=1 origin "$PWF_F3_RUNTIME_SOURCE_HEAD"
git -C "$SOURCE_ROOT" checkout --detach FETCH_HEAD
test "$(git -C "$SOURCE_ROOT" rev-parse HEAD)" = "$PWF_F3_RUNTIME_SOURCE_HEAD"
test -z "$(git -C "$SOURCE_ROOT" status --porcelain=v1 --untracked-files=all)"

cd "$SOURCE_ROOT"
python3 tools/import_upstream_runtime.py check
python3 tools/build_release.py build --output "$CANDIDATE_ZIP"
python3 tools/build_release.py check --archive "$CANDIDATE_ZIP"
ACTUAL_CANDIDATE_SHA256="$(sha256sum "$CANDIDATE_ZIP" | awk '{print $1}')"
test "$ACTUAL_CANDIDATE_SHA256" = "$PWF_F3_CANDIDATE_SHA256"
BOOTSTRAP_RELATIVE_PATH="$(python3 - <<'PY'
import json
from pathlib import Path
manifest = json.loads(Path('upstream-manifest.json').read_text(encoding='utf-8'))
release_path = manifest['managed_runtime']['contracts']['release_artifact']['path']
release = json.loads(Path(release_path).read_text(encoding='utf-8'))
assets = release['external_release_assets']
assert len(assets) == 1
print(assets[0])
PY
)"
test -f "$BOOTSTRAP_RELATIVE_PATH"
bash -n "$BOOTSTRAP_RELATIVE_PATH"

CODEX_HOME="$PWF_F3_CODEX_HOME" \
MANAGED_REQUIREMENTS="$PWF_F3_MANAGED_REQUIREMENTS" \
PLANNING_WITH_FILES_ROOT="$PWF_F3_SKILL_ROOT" \
HOOKS_URL="file://$CANDIDATE_ZIP" \
HOOKS_SHA256="$PWF_F3_CANDIDATE_SHA256" \
bash "$BOOTSTRAP_RELATIVE_PATH" all
DOCTOR_JSON="$(node install.js doctor --json \
  --codex-home "$PWF_F3_CODEX_HOME" \
  --skill-root "$PWF_F3_SKILL_ROOT" \
  --managed-requirements "$PWF_F3_MANAGED_REQUIREMENTS")"
DOCTOR_JSON="$DOCTOR_JSON" python3 - <<'PY'
import json, os
value = json.loads(os.environ['DOCTOR_JSON'])
assert value['healthy'] is True
assert value['managed'] is True
assert value['repairable'] is False
assert value['errors'] == []
assert value['blockers'] == []
PY
printf 'PWF_F3_CLOUD_RUNTIME_TRANSACTION_V1=PASS\nPWF_F3_RUNTIME_SOURCE_HEAD=%s\nPWF_F3_CANDIDATE_SHA256=%s\n' \
  "$PWF_F3_RUNTIME_SOURCE_HEAD" "$PWF_F3_CANDIDATE_SHA256"
```

两次运行都必须取得最终 `exit_code=0`，且打印相同的 runtime HEAD 与 candidate SHA。maintenance 不能 fetch/build/install
时只能 `STOP/INCOMPLETE` 并回到 Discovery，不能退化为“cache 里看起来装过”。本 transaction 只固定 managed runtime 身份；
它不读取或写入项目 `.planning/`，也不证明 workspace lifecycle HEAD。

<a name="f3-execution-inputs"></a>

## 3. Workspace 执行输入与前置检查

每轮从干净 checkout 开始，显式设置并回传这些事实；示例值必须替换，不能照抄：

```bash
set -Eeuo pipefail

PROJECT_ROOT=/absolute/project
PACKAGE_ROOT=/absolute/pwf-codex-cloud-hooks-checkout
PLAN_ID=YYYY-MM-DD-reviewed-plan-id
PROFILE=smart                    # smart 或 autonomous
OWNED_PLAN=/opt/codex/hooks/planning-with-files/owned-plan.py

test "$PROFILE" = smart || test "$PROFILE" = autonomous
test "$(git -C "$PROJECT_ROOT" rev-parse --show-toplevel)" = "$PROJECT_ROOT"
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
test "$(tr -d '\r\n[:space:]' < "$PROJECT_ROOT/.planning/.active_plan")" = "$PLAN_ID"
PLAN_DIR="$PROJECT_ROOT/.planning/$PLAN_ID"
test -d "$PLAN_DIR"
test ! -L "$PLAN_DIR"
test -f "$PLAN_DIR/task_plan.md"
test -f "$PLAN_DIR/findings.md"
test -f "$PLAN_DIR/progress.md"
test ! -e "$PLAN_DIR/.pwf-codex-managed"

WORKSPACE_LIFECYCLE_HEAD="$(git -C "$PROJECT_ROOT" rev-parse HEAD)"
TASK_SHA256="$(sha256sum "$PLAN_DIR/task_plan.md" | awk '{print $1}')"
printf 'F3_WORKSPACE_LIFECYCLE_HEAD=%s\nF3_PLAN_ID=%s\nF3_PROFILE=%s\nF3_TASK_SHA256=%s\n' \
  "$WORKSPACE_LIFECYCLE_HEAD" "$PLAN_ID" "$PROFILE" "$TASK_SHA256"
```

任何路径、HEAD、worktree 或 active pointer 不确定都立即停止。不要让 agent 自动 commit、push、创建/更新 PR、切换
branch 或“修复”仓库；远端写入始终由维护者完成。

<a name="f3-prepare-state"></a>

## 4. Preparation commit（对应 live gate 获批后执行）

先确认 plan 内容已经由人审核。以下函数只原子替换单个文件；整个 preparation 的安全性来自 activation 仍然不存在。
中途失败留下的 partial inert state 必须清理后重来，不能继续 activation。

```bash
write_exact_state() {
  target=$1
  value=$2
  target_dir=${target%/*}
  tmp="$(mktemp "$target_dir/.pwf-f3-state.XXXXXX")"
  printf '%s' "$value" > "$tmp"
  chmod 644 "$tmp"
  mv -- "$tmp" "$target"
}

if test "$PROFILE" = smart; then
  write_exact_state "$PLAN_DIR/.mode" 'inject-smart
'
  test ! -e "$PLAN_DIR/.nonce"
  test ! -e "$PLAN_DIR/.attestation"
  test -z "$(find "$PLAN_DIR" -maxdepth 1 -type f -name 'ledger-*.jsonl' -print -quit)"
else
  NONCE="$(python3 -c 'import secrets; print(secrets.token_hex(8))')"
  test "${#NONCE}" -eq 16
  write_exact_state "$PLAN_DIR/.mode" 'autonomous
'
  write_exact_state "$PLAN_DIR/.nonce" "$NONCE
"
  write_exact_state "$PLAN_DIR/.attestation" "$TASK_SHA256
"
  # F3B 的最小 autonomous 路线允许零 ledger；不要为通过验收伪造 writer/durability。
fi

PROFILE="$PROFILE" PLAN_DIR="$PLAN_DIR" PACKAGE_ROOT="$PACKAGE_ROOT" node <<'NODE'
const { validateActivePlanState } = require(process.env.PACKAGE_ROOT + "/tests/f3-lifecycle-helpers.js");
const actual = validateActivePlanState(process.env.PLAN_DIR);
const expected = process.env.PROFILE + "_prepared";
if (actual !== expected) throw new Error(`expected ${expected}, got ${actual}`);
console.log(`F3_PREPARED_STATE=${actual}`);
NODE

test ! -e "$PLAN_DIR/.pwf-codex-managed"
git -C "$PROJECT_ROOT" diff --check
git -C "$PROJECT_ROOT" status --short
```

上面的 Node 检查负责 repository filenames、regular-file/budget、固定 state framing、profile/token 关系和 task digest；
遇到 ledger 时直接调用当前 exact source 的 `owned-plan.py.normalize_ledger`，不复制第二套 ledger JSON parser。提交
preparation 前，再把 state 复制到 disposable project、只在副本中增加 token，由 installed production consumer完成
第二层 exact ledger/renderer admission：

```bash
VERIFY_ROOT="$(mktemp -d)"
trap 'rm -rf -- "$VERIFY_ROOT"' EXIT
VERIFY_PLAN="$VERIFY_ROOT/.planning/$PLAN_ID"
mkdir -p "$VERIFY_PLAN"
printf '%s\n' "$PLAN_ID" > "$VERIFY_ROOT/.planning/.active_plan"
find "$PLAN_DIR" -maxdepth 1 -type f -exec cp -- '{}' "$VERIFY_PLAN/" \;
write_exact_state() {
  target=$1
  value=$2
  target_dir=${target%/*}
  tmp="$(mktemp "$target_dir/.pwf-f3-state.XXXXXX")"
  printf '%s' "$value" > "$tmp"
  chmod 644 "$tmp"
  mv -- "$tmp" "$target"
}
if test "$PROFILE" = smart; then
  write_exact_state "$VERIFY_PLAN/.pwf-codex-managed" 'codex-managed-v1
'
else
  write_exact_state "$VERIFY_PLAN/.pwf-codex-managed" 'codex-managed-v1 autonomous
'
fi

PREP_PROBE_JSON="$(python3 - "$VERIFY_ROOT" "$PLAN_ID" <<'PY' | "$OWNED_PLAN"
import json, sys
print(json.dumps({
    "schema_version": 2,
    "runtime": "codex",
    "event": {"name": "UserPromptSubmit", "source": None, "session_id": None, "turn_id": None},
    "project": {"root": sys.argv[1], "plan_id": sys.argv[2]},
    "policy": {
        "planning_enabled": True,
        "allowed_profiles": ["legacy", "smart", "autonomous"],
        "opt_in_protocol": "codex-managed-v1",
    },
    "output_budget": {"max_context_chars": 20000, "max_plan_lines": 50, "max_progress_lines": 20},
}))
PY
)"
PREP_PROBE_JSON="$PREP_PROBE_JSON" PROFILE="$PROFILE" python3 - <<'PY'
import json, os
value = json.loads(os.environ["PREP_PROBE_JSON"])
assert value["outcome"] == "context_emitted"
assert value["inject"] is True
assert value["effective_profile"] == os.environ["PROFILE"]
assert value["advisory"] is None
print("F3_PREPARATION_PRODUCTION_PROBE=PASS")
PY
rm -rf -- "$VERIFY_ROOT"
trap - EXIT
test ! -e "$PLAN_DIR/.pwf-codex-managed"
```

若副本 probe 拒绝，保持真实 preparation inert，修复或清理后重新开始。不得为了通过验证在真实 plan 上临时写 token。

维护者审核 diff 后创建 preparation commit；不得由验收模型自动 commit。提交后记录并核验：

```bash
PREPARATION_HEAD="$(git -C "$PROJECT_ROOT" rev-parse HEAD)"
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
test "$(sha256sum "$PLAN_DIR/task_plan.md" | awk '{print $1}')" = "$TASK_SHA256"
test ! -e "$PLAN_DIR/.pwf-codex-managed"
printf 'F3_PREPARATION_HEAD=%s\n' "$PREPARATION_HEAD"
```

## 5. Activation-only commit（对应 live gate 获批后执行）

只有 preparation commit 已审核且当前 worktree 干净时，才最后写入 commit point：

```bash
write_exact_state() {
  target=$1
  value=$2
  target_dir=${target%/*}
  tmp="$(mktemp "$target_dir/.pwf-f3-state.XXXXXX")"
  printf '%s' "$value" > "$tmp"
  chmod 644 "$tmp"
  mv -- "$tmp" "$target"
}

test "$(git -C "$PROJECT_ROOT" rev-parse HEAD)" = "$PREPARATION_HEAD"
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
test "$(sha256sum "$PLAN_DIR/task_plan.md" | awk '{print $1}')" = "$TASK_SHA256"

if test "$PROFILE" = smart; then
  ACTIVATION='codex-managed-v1
'
else
  ACTIVATION='codex-managed-v1 autonomous
'
fi
write_exact_state "$PLAN_DIR/.pwf-codex-managed" "$ACTIVATION"

PROFILE="$PROFILE" PLAN_DIR="$PLAN_DIR" PACKAGE_ROOT="$PACKAGE_ROOT" node <<'NODE'
const { validateActivePlanState } = require(process.env.PACKAGE_ROOT + "/tests/f3-lifecycle-helpers.js");
const actual = validateActivePlanState(process.env.PLAN_DIR);
const expected = process.env.PROFILE + "_armed";
if (actual !== expected) throw new Error(`expected ${expected}, got ${actual}`);
console.log(`F3_ARMED_STATE=${actual}`);
NODE

git -C "$PROJECT_ROOT" diff --check
git -C "$PROJECT_ROOT" status --short
```

维护者确认 diff 只有 `.pwf-codex-managed` 后创建 activation commit，再运行 exact relation check：

```bash
ACTIVATION_HEAD="$(git -C "$PROJECT_ROOT" rev-parse HEAD)"
test "$(git -C "$PROJECT_ROOT" rev-parse "$ACTIVATION_HEAD^")" = "$PREPARATION_HEAD"
test "$(git -C "$PROJECT_ROOT" diff-tree --no-commit-id --name-status --no-renames -r "$ACTIVATION_HEAD")" = \
  "A	.planning/$PLAN_ID/.pwf-codex-managed"
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
test "$(sha256sum "$PLAN_DIR/task_plan.md" | awk '{print $1}')" = "$TASK_SHA256"
printf 'F3_ACTIVATION_HEAD=%s\nF3_ACTIVATION_PARENT=%s\n' "$ACTIVATION_HEAD" "$PREPARATION_HEAD"
```

如果 Git 输出不是 exact 单行，停止；不要用 path filter 隐藏其他改动。

<a name="f3-disarm-commit"></a>

## 7. Disarm commit

F3B opt-out 和 F3C rollback 前都必须先删除 commit point，并由维护者创建单独 disarm commit：

```bash
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
DISARM_PARENT="$(git -C "$PROJECT_ROOT" rev-parse HEAD)"
rm -- "$PLAN_DIR/.pwf-codex-managed"
git -C "$PROJECT_ROOT" diff --check
git -C "$PROJECT_ROOT" status --short
```

提交后核验：

```bash
DISARM_HEAD="$(git -C "$PROJECT_ROOT" rev-parse HEAD)"
test "$(git -C "$PROJECT_ROOT" rev-parse "$DISARM_HEAD^")" = "$DISARM_PARENT"
test "$(git -C "$PROJECT_ROOT" diff-tree --no-commit-id --name-status --no-renames -r "$DISARM_HEAD")" = \
  "D	.planning/$PLAN_ID/.pwf-codex-managed"
test ! -e "$PLAN_DIR/.pwf-codex-managed"
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
printf 'F3_DISARM_HEAD=%s\nF3_DISARM_PARENT=%s\n' "$DISARM_HEAD" "$DISARM_PARENT"
```

保留的 `.mode`、nonce、attestation 或 ledger 此时必须 inert。关闭 planning scope 时应显式清退这些 state；不得把它们
搬入 history scope。F3C 不允许在未提交 disarm 时先回滚 runtime。

<a name="f3-validation-dag"></a>

## 8. 隔离 validation DAG

smart 与 autonomous 必须从同一个 markerless baseline 分叉验证，不能把 smart 的残留 state 当成 autonomous 的准备输入，
也不能用一个长线性 branch 掩盖 parent 关系。validation refs 只由维护者创建/选择；验收 agent 不 commit、push、PR 或移动
ref。F3B1 已在 disposable local Git repo 静态干跑下列图，但没有在真实项目创建任何 machine state：

```text
markerless baseline
├─ S_PREP  --only .mode=inject-smart
│  └─ S_ARM   --only add .pwf-codex-managed
│     └─ S_DISARM --only delete .pwf-codex-managed
│        └─ S_REARM --only add .pwf-codex-managed
└─ A_PREP  --only .mode/.nonce/.attestation
   └─ A_ARM   --only add .pwf-codex-managed
      └─ A_DISARM --only delete .pwf-codex-managed
         └─ A_REPREP --only task_plan.md/.nonce/.attestation
            └─ A_REARM --only add .pwf-codex-managed
```

每条边都要求 child 的 parent 精确等于上表 predecessor，worktree clean，`diff-tree --no-renames` 路径集合 exact；每个 armed
节点都要经过 installed `owned-plan.py` read-only probe。smart 只在 F3B2 验证，autonomous 与 tamper 只在 F3B3 验证。
任一节点失败即废弃该隔离 branch，从已审核 markerless baseline 重来，不能把失败节点“修补成”下一个 stage。

<a name="f3-tamper-worktree"></a>

## 9. Autonomous bounded tamper（仅 F3B3）

tamper 只在可丢弃的 autonomous armed validation checkout 中执行，且只允许修改当前 plan 的 `task_plan.md`。它不 commit、
不 push、不创建 PR；验证 `canary_only + advisory=state_unsafe` 后直接销毁 checkout。以下 block 在 F3B1 **只做语法和静态
边界检查，不执行**：

```bash
test "$PROFILE" = autonomous
test "$(git -C "$PROJECT_ROOT" rev-parse HEAD)" = "$AUTONOMOUS_ACTIVATION_HEAD"
test -z "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)"
printf '\nF3B_TAMPER_ONLY\n' >> "$PLAN_DIR/task_plan.md"
test "$(git -C "$PROJECT_ROOT" status --porcelain=v1 --untracked-files=all)" = \
  " M .planning/$PLAN_ID/task_plan.md"

# 用第 6 节的 installed production probe 发起同一 request；只接受下面的关系。
TAMPER_PROBE_JSON="$PROBE_JSON" python3 - <<'PY'
import json, os
value = json.loads(os.environ['TAMPER_PROBE_JSON'])
assert value['outcome'] == 'state_unsafe'
assert value['inject'] is False
assert value['effective_profile'] is None
assert value['advisory'] == 'state_unsafe'
print('F3B_AUTONOMOUS_TAMPER_REFUSAL=PASS')
PY
```

若 status 不是 exact 单一路径，或 runtime 回退 legacy/输出 partial plan，立即失败并保留证据；不要 reset 一个准备继续使用的
真实工作区。该 checkout 本身就是 disposable evidence fixture，结束后整体销毁。F3B1 不把这个负向 case 变成 production writer。

<a name="f3-evidence-record"></a>

## 10. Exact evidence record

每个 F3B2/F3B3 stage 生成一个 JSON object，并用当前 exact runtime source checkout 中的
`tests/f3-lifecycle-helpers.js::validateF3EvidenceRecord` 校验。字段集合固定如下；不接受 `latest`、模型判断、自由文本 PASS 或
额外自认证字段：

```json
{
  "schema_version": 1,
  "profile": "smart",
  "stage": "armed",
  "runtime_source_head": "<40 lowercase hex>",
  "candidate_sha256": "<64 lowercase hex>",
  "workspace_lifecycle_head": "<40 lowercase hex>",
  "worktree": "clean",
  "session_start_sources": ["startup", "resume"],
  "user_prompt_observed": true,
  "hook_context": "smart",
  "effective_profile": "smart",
  "advisory": null,
  "doctor_healthy": true,
```
