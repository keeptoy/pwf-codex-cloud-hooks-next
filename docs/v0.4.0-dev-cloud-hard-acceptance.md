## F2B 验收增量与模板同步

- **新增风险面：** adapter/runtime capability 现为 exact `[legacy, smart, autonomous]`；autonomous reader 增加
  profile-bound activation、task attestation、nonce、bounded JSONL ledger 与 post-render identity revalidation。
- **portable 增量：** 通用 Source/Candidate sequence 会动态纳入新增 tests，Linux 必须零 skip，直接覆盖 autonomous
  context、零 ledger、raw-progress no-read、invalid/budget/link/race/tamper、smart/legacy compatibility 和 `gate` denial。
- **供应链增量：** 仍由 manifest-routed runtime bundle v2 校验 adapter、owned-plan 和 request schema 的新 hash；entry
  数量、installed inventory、adapter-only policy 与 pristine upstream helper inventory 不新增第二份 authority。
- **B～E 黑盒：** 不变，继续证明 markerless legacy 默认；F2B no-live gate 不创建真实 activation state。真实 prepare、
  activation、disarm/re-arm、Fresh/Resume/cache 与 rollback 属 F3，当前禁止执行。
- **完成判据：** exact checkout 上 Linux portable suite 零 fail/skip、deterministic candidate、bootstrap install、B～E、
  post-Resume doctor/deep check 全部通过后，才把本表 F2B Cloud 行改为 `PASS` 并新增 exact evidence。

### F2A test-harness deviation 与协议修正

首次 post-Resume 调用实际复用了退役的 v1 deep-check 脚本，因读取 `release-artifact-v1`、`runtime-bundle-v1` 与
`bundle.files` 失败；当前仓库 9.1 当时已经从 manifest 动态路由 v2 contract，并使用
`upstream_files/local_files/installed_contracts`，因此该失败分类为 **stale external acceptance script**，不是产品、
安装或 current template defect。旧脚本只读，未改变安装或 workspace；修正后的新 invocation 完整重跑并得到
doctor healthy、12 项 installed inventory 与 bundle authority 一致、4 个 upstream pristine、adapter-only policy、
零 snapshot residue 和 `PWF_SC_POST_RESUME=PASS`，证明修正后的 v2 deep-check 逻辑本身可通过。

该轮 Cloud 模型在发现旧脚本后自行修复并创建 PR，使 9.1 checkout HEAD 从原始 candidate 前移；它因此只保留为
诊断/功能证据，不作为最终 exact F2A gate 封账。后继模板已明确禁止 branch/commit/push/PR 与自动修复，只允许 C
段修改 canonical planning fixture；9.1 用简短 guard 拒绝 `.planning/` 之外的仓库改动，并打印当前 deep-check HEAD。
4.1 的 Source/Candidate HEAD 与 ZIP SHA 继续由最终 evidence writeback 对账，不再引入跨 task 临时状态协议。

模板不再输出自证式 `PWF_DEEP_CHECK_PROTOCOL` 口号，而是从 manifest 当前路由打印 release/bundle contract 的
path、id、schema 与 installed root。后继 Fresh run 已从同一 exact HEAD 回传 Linux suite、candidate identity、
B～E blackbox 与 9.1 摘要并闭合下方 F2A evidence；此前发生 HEAD 漂移的诊断轮不参与最终封账。

## F1B 验收增量（historical gate instance）

- F0 建立 `v0.4.0-dev` package/Release identity、外部 bootstrap 和 candidate/accepted 治理窗口；F1A
  原子迁移 source manifest schema 4、runtime bundle v2、Release artifact v2、adapter/四项 ABI
  placement 与 entry-owned mode。
- F1B 只轮转 plan request/result v2；catch-up 继续使用 v1。adapter producer 与 owned runtime capability
  均固定为 `allowed_profiles=[legacy]`，Host 输出、canary、上下文顺序和 managed-legacy 行为必须保持不变。
- `.mode` reader/normalizer 作为 inactive seam 随 runtime 安装，但 production 不得调用；nonce、attestation
  和 ledger reader 不得存在。Linux suite 必须零 skip 执行 future-profile refusal、legacy zero-read、unsafe
  mode/link/race 与旧 marker 不影响输出等证明。
- candidate installer 只接受当前完整状态或 transition contract 精确列出的 v0.3.5 predecessor。exact forward
  migration、tamper-before-write refusal 与 clean rollback 已由 ref-aware 本地 oracle 验证；tagless
  Source/Candidate Cloud 不伪造 refs，也不把 publication-only oracle 改写成 no-live 结果。
- exact current id/source inventory guard 继续拒绝未准入文件；Cloud setup 必须从当前 manifest/bundle 动态
  验证 v2 paths、hash、entry count、installed inventory 与 executable mode，不手填历史数量。
- 本次验收增量没有改写 B～E 黑盒提示词；它们继续验证真实 Host 行为与 legacy baseline 等价，F1B 的
  新增证明来自 Linux 零 skip suite 和 candidate 安装后的 exact deep check。
