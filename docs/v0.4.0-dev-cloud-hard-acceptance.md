### F2B asynchronous runner misclassification note

该轮 9.1 首次执行时，Cloud 命令工具在短暂 initial yield 后只返回了 `PWF_WORKTREE_CHANGES=PLANNING_ONLY`、doctor
JSON 与一个仍在运行的 session。Cloud 模型只读取该 stdout 分片，没有继续轮询，也没有取得最终 exit code，却错误声称
脚本以 exit code 1 失败。后继执行保留并轮询同一类异步 session，取得剩余 deep-check PASS 输出与明确 exit code 0，证明
脚本、Bash/Python heredoc、操作系统和安装状态均无故障；首次说法属于 **asynchronous tool-state misclassification**，
不是 product、script、platform 或 prompt-escaping defect，也不计为一次真实 gate failure。

因此通用模板已把“stdout 不是进程状态”加入每个 Cloud task 的强制权限前缀与 hard-stop 规则：有 session/running 或无
最终 exit code 时必须持续轮询；session 丢失只能报告 `INCOMPLETE/UNKNOWN`；禁止根据缺少 PASS marker 猜 FAIL，更禁止
声称工具未实际返回的 exit code。该治理适用于 test、build、install、download 和 deep check 等所有长命令，不为 PWF
脚本另建特殊分支。
