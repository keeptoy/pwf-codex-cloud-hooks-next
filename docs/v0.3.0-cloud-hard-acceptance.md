## 2. 冻结行为

stable v0.3.0 不增加或删除 lifecycle 行为：

| Event | 输出顺序 | 失败语义 |
|---|---|---|
| `SessionStart` | canary → 可选 catch-up → 可选 canonical plan | plan failure 为 canary-only；catch-up failure 保留健康 plan |
| `UserPromptSubmit` | canary → 可选 canonical plan | unsafe/invalid/non-injecting result 不注入 |

两者仍执行 installer 管理的 sibling `owned-plan.py`；SessionStart 只把已经验证的 exact project
交给 `owned-catchup.py`。global PWF v3.8.2 Skill 保持 pristine。Managed policy 只注册 adapter。

## 3. Gate 顺序与停止条件

必须严格按以下顺序：

1. S1 checkpoint 并冻结 exact commit；
2. S2 Fresh Cloud no-live prepublication seal；
3. 维护者单独授权 S3；
4. 创建 `v0.3.0` tag/Release 并上传两个资产；
5. A：重新下载资产、安装与静态健康；
6. B：全新 task 自动 startup/UserPrompt；
7. C：创建真实 planning baseline；
8. D：立即验证 canonical UserPrompt；
9. E1：发送长 wrapper 并结束当前 task；
10. E2：Resume 同一个 task；
11. F：post-resume doctor/inventory/residue；
12. 全部 PASS 后才提升 v0.3.0 为 rollback baseline。

任一步失败立即停止，不发布后续资产、不修改 live 安装来掩盖候选问题，也不进入 Product Phase 4。
