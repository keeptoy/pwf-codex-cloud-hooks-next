## F1B 验收增量（historical gate instance）

- F0 建立 `v0.4.0-dev` package/Release identity、外部 bootstrap 和 candidate/accepted 治理窗口；F1A
  原子迁移 source manifest schema 4、runtime bundle v2、Release artifact v2、adapter/四项 ABI
  placement 与 entry-owned mode。
- F1B 只轮转 plan request/result v2；catch-up 继续使用 v1。adapter producer 与 owned runtime capability
  均固定为 `allowed_profiles=[legacy]`，Host 输出、canary、上下文顺序和 managed-legacy 行为必须保持不变。
- `.mode` reader/normalizer 作为 inactive seam 随 runtime 安装，但 production 不得调用；nonce、attestation
  和 ledger reader 不得存在。Linux suite 必须零 skip 执行 future-profile refusal、legacy zero-read、unsafe
  mode/link/race 与旧 marker 不影响输出等证明。
- candidate installer 只接受当前完整状态或 transition contract 精确列出的 v0.3.5 predecessor。exact forward
  migration、tamper-before-write refusal 与 clean rollback 已由 ref-aware 本地 oracle 验证；tagless
  Source/Candidate Cloud 不伪造 refs，也不把 publication-only oracle 改写成 no-live 结果。
- exact current id/source inventory guard 继续拒绝未准入文件；Cloud setup 必须从当前 manifest/bundle 动态
  验证 v2 paths、hash、entry count、installed inventory 与 executable mode，不手填历史数量。
- 本次验收增量没有改写 B～E 黑盒提示词；它们继续验证真实 Host 行为与 legacy baseline 等价，F1B 的
  新增证明来自 Linux 零 skip suite 和 candidate 安装后的 exact deep check。
